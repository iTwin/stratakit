Migrating from iTwinUI

Learn how to migrate from iTwinUI to StrataKit

This guide provides the necessary steps for migrating from iTwinUI to StrataKit.

Note

Migration to StrataKit can be done gradually, since iTwinUI can coexist in the same application by utilizing the StrataKit theme bridge.

Migration steps

Section titled “Migration steps”

  1. Set up StrataKit

    Follow the set up StrataKit guide to install the necessary dependencies and set up your project.

  2. Enable the StrataKit theme bridge

    Pass the StrataKit Root into the as prop of the iTwinUI ThemeProvider to render a single DOM element.

    Specify the Root props directly on the ThemeProvider component.

    Finally, activate the themeBridge future flag.

    Note

    If StrataKit’s accent color is not compatible with your existing UI, see visual transition.

  3. Replace @itwin/itwinui-icons-react with @stratakit/icons

    Replace the usage of iTwinUI icons from @itwin/itwinui-icons-react with their StrataKit counterparts. Refer to the use StrataKit icons section below for the full icon mapping.

    Once all usage of @itwin/itwinui-icons-react has been replaced, it is safe to remove the dependency.

  4. Replace usage of @itwin/itwinui-react

    Replace the usage of components from @itwin/itwinui-react with their StrataKit counterparts. Some components are provided by @mui/material, while others live in @stratakit/structures. Refer to the use StrataKit components section below for the full component mapping.

    Once all usage of @itwin/itwinui-react has been replaced, it is safe to remove the dependency.

Visual transition

Section titled “Visual transition”

By default, StrataKit uses its preferred “aurora” green accent color. Some legacy applications rely on a blue accent color, especially when parts of the UI are not implemented with up-to-date iTwinUI components. In these cases, the aurora accent color can clash with the existing UI or require significant adjustments to it.

To ease the visual transition, use StrataKit’s “cobalt” accent color, which is designed for better compatibility with iTwinUI’s color palette. Set the unstable_accentColor prop on the Root component to apply the accent color to all StrataKit components.

Once the visual transition is complete, remove the unstable_accentColor prop to continue using StrataKit’s preferred accent color.

Alert

Section titled “Alert”

Replace the Alert component from @itwin/itwinui-react with the Alert component from @mui/material. See Alert examples for reference.

  • Replace status with the severity prop.
  • MUI Alert has no equivalent to iTwinUI Alert’s sticky prop. Set the CSS position property to sticky instead.

Anchor

Section titled “Anchor”

Replace the Anchor component from @itwin/itwinui-react with the Link component from @mui/material. See Link examples for reference.

  • Replace external by following the external Link example.
  • Remove underline. StrataKit handles underlines automatically.

Avatar

Section titled “Avatar”

Replace the Avatar component from @itwin/itwinui-react with the Avatar component from @mui/material. See Avatar examples for reference.

  • Replace size with the CSS block-size and inline-size properties.
  • Replace status by wrapping the Avatar in Badge.
  • MUI Avatar does not assign background colors automatically like iTwinUI.

AvatarGroup

Section titled “AvatarGroup”

Replace the AvatarGroup component from @itwin/itwinui-react with the AvatarGroup component from @mui/material. See AvatarGroup examples for reference.

  • MUI AvatarGroup has no equivalent to iTwinUI AvatarGroup’s animated prop.
  • Replace overflow handling with the renderSurplus prop.

Badge

Section titled “Badge”

Replace the Badge component from @itwin/itwinui-react with the Badge component from @mui/material. See Badge examples for reference.

  • Replace status background colors with the color prop.
  • Replace soft background colors by omitting the color prop. StrataKit does not provide separate non-status badge colors.

Blockquote

Section titled “Blockquote”

Replace the Blockquote component from @itwin/itwinui-react with the native <blockquote> element.

Breadcrumbs

Section titled “Breadcrumbs”

Replace the Breadcrumbs component from @itwin/itwinui-react with the Breadcrumbs component from @mui/material. See Breadcrumbs examples for reference.

  • Replace iTwinUI Breadcrumbs’ truncation by following the Breadcrumbs truncation example.

Button

Section titled “Button”

Replace the Button component from @itwin/itwinui-react with the Button component from @mui/material. See Button examples for reference.

  • Replace styleType="cta" with color="primary".
  • Replace styleType="borderless" with variant="text".
  • Replace styleType="high-visibility" with the default Button. If it is the main action of a dialog or page, use color="primary".
  • The size and loading props require no changes.

ButtonGroup

Section titled “ButtonGroup”

Replace the ButtonGroup component from @itwin/itwinui-react with the ButtonGroup component from @mui/material. See ButtonGroup examples for reference.

  • Replace <ButtonGroup role="toolbar"> with Toolbar from @stratakit/structures for grouped commands, or with MUI ToggleButtonGroup when the buttons select an option.
  • Replace a ButtonGroup that combines buttons with an Input with TextField and its startAdornment or endAdornment props.

Carousel

Section titled “Carousel”

There is no direct replacement for the Carousel component from @itwin/itwinui-react. StrataKit discourages the use of carousels.

Checkbox

Section titled “Checkbox”

Replace the Checkbox component from @itwin/itwinui-react with the Checkbox component from @mui/material. See Checkbox examples for reference.

  • Replace status="negative" with error on a wrapping FormControl and a FormHelperText message. See the Checkbox error example.
  • MUI Checkbox has no equivalent to iTwinUI Checkbox’s loading prop. Render CircularProgress in place of the checkbox while loading.
  • MUI Checkbox has no equivalent to iTwinUI Checkbox’s visibility prop.

Code

Section titled “Code”

Replace the Code component from @itwin/itwinui-react with the Typography component from @mui/material rendered as <code>. See Typography examples for reference.

ColorPicker

Section titled “ColorPicker”

Replace the ColorPicker component from @itwin/itwinui-react with the color picker composite component.

  • For a limited set of colors, use the Select component from @mui/material instead.

ComboBox

Section titled “ComboBox”

Replace the ComboBox component from @itwin/itwinui-react with the Autocomplete component from @mui/material. See Autocomplete examples for reference.

  • Replace multiple with MUI Autocomplete’s multiple prop.

DatePicker

Section titled “DatePicker”

Replace the DatePicker component from @itwin/itwinui-react with the DatePicker component from @mui/x-date-pickers. See DatePicker examples for reference.

  • Replace enableRangeSelect with two DatePickers, one for the start date and one for the end date.
  • For a standalone calendar, use the DateCalendar component from @mui/x-date-pickers.

Dialog

Section titled “Dialog”

Replace the Dialog component from @itwin/itwinui-react with the Dialog component from @mui/material. See Dialog examples for reference.

  • MUI Dialog has no equivalent to iTwinUI Dialog’s isDismissible prop. Add a close IconButton when dismissal is allowed; otherwise, omit it, set disableEscapeKeyDown, and ignore "backdropClick" in onClose.
  • MUI Dialog has no equivalent to iTwinUI Dialog’s isDraggable prop. Implement dragging with react-draggable or another third-party library.
  • MUI Dialog has no equivalent to iTwinUI Dialog’s isResizable prop. To allow resizing, apply CSS resize: both and overflow: auto to the dialog paper using slotProps.paper.className, and set appropriate size limits.
  • Replace styleType="fullPage" with the fullScreen prop.
  • MUI Dialog has no equivalent to iTwinUI Dialog’s placement prop. Position the dialog paper with CSS position: absolute instead.
  • MUI Dialog has no equivalent to iTwinUI Dialog’s non-modal behavior. See MUI’s non-modal dialog guidance.

Divider

Section titled “Divider”

Replace the Divider component from @itwin/itwinui-react with the Divider component from @mui/material. See Divider examples for reference.

DropdownButton

Section titled “DropdownButton”

Replace the DropdownButton component from @itwin/itwinui-react with a Button that opens a Menu, both from @mui/material. See Menu examples for reference.

DropdownMenu

Section titled “DropdownMenu”

Replace the DropdownMenu component from @itwin/itwinui-react with the Menu component from @mui/material. See Menu examples for reference.

  • Replace a start icon with an Icon inside ListItemIcon before the text in MenuItem.
  • Replace an end icon with an Icon after ListItemText in MenuItem, aligned to the end.
  • Replace a sublabel with ListItemText’s primary and secondary props inside MenuItem.
  • MUI MenuItem has no equivalent to iTwinUI MenuItem’s submenu support.
  • Replace MenuDivider with a Divider between MenuItem components.

ExpandableBlock

Section titled “ExpandableBlock”

Replace the ExpandableBlock component from @itwin/itwinui-react with the Accordion component from @mui/material. See Accordion examples for reference.

  • Replace a caption with two Typography elements inside AccordionSummary.
  • Replace an accordion of blocks with adjacent Accordion components. If only one should be open at a time, control their expanded props with shared state.
  • MUI Accordion has no equivalent to iTwinUI ExpandableBlock’s status prop. Place a status Icon in AccordionSummary instead.
  • MUI Accordion has no equivalent to iTwinUI ExpandableBlock’s size prop. Its default size matches iTwinUI’s size="small".
  • Replace styleType="borderless" with variant="elevation".

Fieldset

Section titled “Fieldset”

Replace the Fieldset component from @itwin/itwinui-react with the native <fieldset> element.

FileUpload

Section titled “FileUpload”

Replace the FileUpload component from @itwin/itwinui-react with the file selection composite component.

Flex

Section titled “Flex”

Replace the Flex component from @itwin/itwinui-react with the Stack component from @mui/material.

  • Replace gap prop with the spacing prop. Convert the value to a number representing the distance in StrataKit spacing units.
  • Replace the flexDirection property with the direction prop.
  • Remove alignItems, justifyContent, and flexWrap. Apply CSS styling that sets those properties.

Footer

Section titled “Footer”

Replace the Footer component from @itwin/itwinui-react with the footer composite component.

Header

Section titled “Header”

Replace the Header component from @itwin/itwinui-react with the header composite component.

IconButton

Section titled “IconButton”

Replace the IconButton component from @itwin/itwinui-react with the IconButton component from @mui/material. See IconButton examples for reference.

  • Replace styleType="cta" with color="primary" and variant="outlined".
  • Replace styleType="high-visibility" with variant="outlined". If it is the key action, add color="primary".
  • Replace styleType="default" with variant="outlined".
  • Remove styleType="borderless"; the default MUI IconButton appearance is borderless.

InputGrid

Section titled “InputGrid”

There is no direct replacement for the InputGrid component from @itwin/itwinui-react, which groups a label, field, and message. Compose an equivalent layout from MUI components instead.

  • For a text input, use TextField with label and helperText, such as <TextField label="Name" helperText="Message" />.

Overlay

Section titled “Overlay”

Replace the Overlay component from @itwin/itwinui-react with the Backdrop component from @mui/material. See Backdrop examples for reference.

  • Replace content with Backdrop’s children, such as a loading message or CircularProgress. Control visibility with the open prop.
  • iTwinUI Overlay blurs its children and makes them inert. MUI Backdrop only covers them visually. Set inert on the underlying content while the backdrop is shown, keep the backdrop outside the inert subtree, and add a blur with CSS if needed.
  • To cover only a section, place the backdrop in a positioned wrapper and position it with CSS. MUI Backdrop is fixed to the viewport by default.
  • For a loading state, describe it in accessible text and set aria-busy on the affected region. Use a Dialog instead if the foreground requires modal interaction and focus management.

Section titled “Slider”

Replace the Slider component from @itwin/itwinui-react with the Slider component from @mui/material. See Slider examples for reference.

Note

MUI Slider supports more than two values, but only highlights the range between the first and last value.

  • Replace values with value or defaultValue. Pass a single number for a single value, or [number, number] for a range.
  • Replace trackDisplayMode="none" with track={false}.
  • Replace trackDisplayMode="even-segments" with track="inverted".
  • Replace trackDisplayMode="odd-segments" with track="normal", or remove it.
  • Replace trackDisplayMode="auto" with track="normal" or track="inverted". If the number of values varies, alternate between them based on the count.
  • Replace tickLabels with the marks prop. See the Slider marks example.
    • Use marks={true} to place a mark at every step.
    • Use marks={array} to provide custom values and labels.
  • Replace tooltipProps with valueLabelDisplay. Set it to "off" to hide the value label when the value is displayed elsewhere.
  • Replace minLabel and maxLabel with a Stack that wraps the labels and Slider. See the Slider tooltip example.
